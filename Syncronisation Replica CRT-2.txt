TASK 1: OPLOG - WHAT IT IS
=====================================================================

REM The oplog is a special CAPPED collection: local.oplog.rs
REM   - Exists on every replica set member.
REM   - Primary writes every data change into it (insert/update/delete/command).
REM   - Secondaries read the oplog of their sync source and APPLY the same operations.
REM   - Capped = fixed size. When full, the oldest entries are overwritten.
REM   - Entries are IDEMPOTENT: applying the same entry twice gives the same result.

REM Fields of an oplog entry:
REM   ts   = timestamp (seconds + counter), unique and ordered
REM   t    = term (increases after every election)
REM   op   = operation type
REM   ns   = namespace (database.collection)
REM   o    = the operation itself (document inserted / update description / command)
REM   o2   = for updates: which document was updated (the _id)
REM   wall = wall clock time

REM Operation types (op):
REM   i = insert     u = update     d = delete
REM   c = command (createCollection, createIndexes, drop ...)
REM   n = no-op (heartbeat / informational)
